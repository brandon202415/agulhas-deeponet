## Conventions this session established (apply them)

- **Dual-file discipline**: every content change goes into both `Agulhas_DeepONet_Manuscript.md` (source of truth) and `.tex` (hand-mirrored), identically in substance. Same now applies to the new `Agulhas_DeepONet_Supplement.{md,tex}` pair.
- **`.tex` table refs use `\ref{tab:label}` exclusively, never hardcoded "Table N"** — confirmed zero hardcoded instances before the Section 3 restructuring, which is why physically reordering table content blocks in `.tex` auto-renumbers every cross-reference for free. `.md` has no such mechanism; every "Table N" mention there was fixed by hand with unique surrounding context. Keep this discipline — if you add a new table reference in `.tex`, use `\ref{}`, not a literal number.
- **Verification discipline**: after any batch of edits, re-grep table counts (`grep -c '^\*\*Table [0-9]'` in `.md` vs `grep -c '\\caption{'` in `.tex`) and section-reference counts (`Sec\. 3\.[0-9]` / `Sec\.~3\.[0-9]`, similarly for `4\.`) — they should match exactly between files. This caught several real bugs this session and should not be skipped as "probably fine."
- **Never fabricate or estimate cluster/analysis results.** Everything numeric in this handoff and in the manuscript was either computed directly from real local result files (with explicit staleness checks — see next point) or came from real pasted `sbatch` output the user ran.
- **Check file timestamps/provenance before trusting a result file**, especially anything with "results" in a directory name — this session found *two* separate stale-duplicate-directory traps (`eddy_tracking/stat_test_*.json` files predating the matplotlib fix; `results_r3_std/` being a stale pre-fix duplicate of the real `results_r3_std_mplfix_check/`). When in doubt, check `ls -la` timestamps and file sizes against a known-good sibling before using a result file's numbers in the manuscript.
- **PDF build check**: `tectonic Agulhas_DeepONet_Manuscript.tex` (and separately for the Supplement), then `grep -ic undefined` on the `.log` (pass `--keep-logs`, clean up the `.log` file after — it's not meant to be a tracked artifact). Cosmetic overfull-hbox warnings up to ~50–90pt have been tolerated throughout without action; anything in the *hundreds* of pt (this session hit one at 283pt from a naive 7-column table) is a real bug, not cosmetic — fix with `\small` + grouped `\multicolumn` headers or similar, don't just ignore it because it "looks like the same kind of warning."
- **User's default working mode**: paste adversarial referee-style feedback, expect triage into (a) direct fixes executed immediately without re-asking, (b) genuinely new-scope items (new cluster runs, new analysis code, big structural/editorial calls) surfaced via `AskUserQuestion` before acting. This has worked well for five rounds; keep doing it rather than either asking permission for everything or unilaterally deciding everything.
